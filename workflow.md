# Chapter-drafting protocol

Use this companion procedure with the existing [AI+1 constitution](https://github.com/nikbearbrown/ai1-cli/blob/main/AI1.md) and [Conductor](https://github.com/nikbearbrown/ai1-cli/blob/main/CONDUCTOR.md). It is an author-review proposal, not an installed replacement skill. It does not authorize skipping phases or writing in a book before the relevant gates are signed.

## Ask for one chapter

> Use AI+1 to prepare the first draft of one chapter for these learners, from these authorized sources. Start with the current book phase and reuse verified material. State what the student must be able to do without AI. Before handing me a draft, run the AI Readiness check, then review the actual teaching evidence against R1–R6. Separate what the draft proposes, what you verified, and what requires my decision. Do not publish or sign a gate.

### Input and output contract

- **Inputs:** one chapter identifier, audience, expected skill, source locks, upstream book gates, content and data permissions, and instructor-defined AI rules where available.
- **Chapter packet:** draft and outline, outcome map, source and claim ledger, one worked example, one unaided attempt and independent check, a disciplinary AI exercise where appropriate, one transfer assessment, a scoring guide, and any figure/alt-text briefs.
- **Audit packet:** immutable input revision, tool and local test receipt, automatic ARC result, qualitative R1–R6 notes with quoted locations, decision owner, open issues, and applicability to this chapter versus the whole course. Keep student-facing materials and instructor-only solutions separate.

## Required audit handoff

1. Check the canonical book phase and prior artifact receipts. Pause for the human if a prerequisite gate is unsigned or a required approved artifact is unverified. Do not manufacture signatures.
2. Use permitted evidence only. For each material claim, retain the exact passage, identifier, page or deterministic check; a working link is not sufficient evidence. Label synthetic examples.
3. Build the first draft using relevant existing rough chapters, lecture notes, slides, examples and exercises. Preserve provenance, reuse approved material, fill gaps, and run the fact checker before the readiness screen. Fact-check findings remain evidence for review, not a signed release gate.
4. After fact-checking the packet, run the existing pinned ARC locally in a scratch workspace on a copy of the selected text. The command receipt records the tool version, scope and counts. Never paste institutional or student material into an unapproved service.
5. Compare the automatic six-question screen against the actual packet. For every question record: **supported in draft**, **partial**, **not supplied**, or **does not apply** with reasoning. Separately record faculty decision or approval; do not infer it.
6. Revise the draft using both reports and recheck changed claims and activities. Keep weaknesses visible in the human handoff. Design gaps go back to the draft; a course policy, tool access, delivery settings and grading go to the course team. Failed required checks block any “ready” label. A first draft with gaps can still be sent privately for review, provided the gaps are visible.
7. Run [CAJAL](https://github.com/nikbearbrown/ai1-cli/blob/main/chapters/88-appendix-cajal.md) after revision to identify figures needed for learning. Brief them, reuse or make the figures, and check layout and subject accuracy separately. Check alt text, captions, provenance and whether the figure agrees with the text. Carry unfinished figures as explicit holds.
8. Make [review proofs](exports-and-design.md) in the requested formats under the default or instructor-supplied design. The proposed MCP hands off the editable draft, figures, export previews, sources and unresolved issues. The human expert reads, checks and edits the complete draft as the last pass. Rebuild any changed proofs; no automatic sync, import, gate signature, or publication.

For the first iteration use a single chapter on a safely verifiable topic and compare an unaided transfer task with a model-aided draft check. Keep actual student studies out of this initial pilot.
