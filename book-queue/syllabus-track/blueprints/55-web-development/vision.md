## Editorial proposal

**Central argument:** A working preview is not enough. The developer must be able to explain how a change fits the existing application, predict what it should do when something fails, and show independent evidence that the diff meets the agreed contract.

**Reader:** A learner who can read and edit basic code but has not yet taken responsibility for a change across a web stack. The book teaches enough HTML, CSS, browser state, HTTP, and storage to inspect and test changes rather than simply generate them.

**Engentic practice:** The human reads the project first, defines acceptance cases and permissions, delegates only a bounded change, checks the actual diff and system behavior, and retains preview and release authority. A coding agent may propose plans, patches, or tests; it cannot independently establish that its own work meets the requirements.

**Placement:** Main queue row 12, Design Engineering, overlaps in briefing and review. The distinctive web outcome would be an evidence-backed full-stack change that survives keyboard use, failures, refresh, and a fresh preview.
