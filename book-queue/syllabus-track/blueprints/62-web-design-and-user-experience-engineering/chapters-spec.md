# Chapter specifications

**Private Blueprint only. Draft route: `compare-scope`. Evidence: `matched-source`. No sign-off.**

Each entry is a proposed chapter, not drafted prose.

## 1. Map the task before layout

- **Observable capability:** Translate a task flow into hierarchy
- **Teaching blocks:** entry; progression; states; labels
- **Original worked example to write:** A local workshop registration page
- **Assessable practice:** Map an empty, full and error state

## 2. Introduce state only when needed

- **Observable capability:** Explain when a component needs state and avoid redundant fields
- **Teaching blocks:** React basics; props; state; derived view
- **Original worked example to write:** A workshop availability filter
- **Assessable practice:** Build a state diagram and compare two rendering cases

## 3. Build semantic structure

- **Observable capability:** Choose controls compatible with a keyboard journey
- **Teaching blocks:** structure; labels; focus; forms
- **Original worked example to write:** A labeled event signup with validation
- **Assessable practice:** Explain and test the keyboard path

## 4. Adapt layout by content

- **Observable capability:** Make layout changes without hiding required information
- **Teaching blocks:** responsive hierarchy; wrapping; spacing; viewport tests
- **Original worked example to write:** A narrow-width event description
- **Assessable practice:** Record two viewport and text-size outcomes

## 5. Test and revise

- **Observable capability:** Use reproducible checks in a design critique
- **Teaching blocks:** manual checks; errors; contrast; regression
- **Original worked example to write:** A form error not announced to the reader
- **Assessable practice:** Write a defect report with expected behavior
