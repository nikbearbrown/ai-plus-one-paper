# Chapter specifications

**Private Blueprint only. Draft route: `ready-for-draft-review`. Evidence: `matched-source`. No sign-off.**

Each entry is a proposed chapter, not drafted prose.

## 1. From request to contract

- **Observable capability:** Translate an ambiguous sponsor statement into an acceptance test.
- **Teaching blocks:** Problem framing; intended users; exclusion list; measurable success.
- **Original worked example to write:** Clarify a fictitious community clinic's request to improve appointment reminders.
- **Assessable practice:** Deliver a one-page scope with three testable outcomes and two exclusions.

## 2. Project interfaces and checkpoints

- **Observable capability:** Coordinate discipline-specific tasks without blocking integration.
- **Teaching blocks:** Work breakdown; interfaces; dependencies; decision log.
- **Original worked example to write:** Divide a campus recycling dashboard among UX, data and implementation roles.
- **Assessable practice:** Write interface contracts and a timeline with one identified dependency risk.

## 3. Evidence reviews and scope tradeoffs

- **Observable capability:** Use feedback to revise a prototype without inflating scope.
- **Teaching blocks:** Prototype review; test scenarios; uncertainty; decision ownership.
- **Original worked example to write:** Choose between better data import and a larger dashboard under deadline.
- **Assessable practice:** Document alternatives with evidence and update two acceptance tests.

## 4. Handoff and individual proof

- **Observable capability:** Make a project usable and auditable by the next team.
- **Teaching blocks:** Runbook; operational limits; reproducibility; contribution trace.
- **Original worked example to write:** Hand off a synthetic advising scheduler to an unfamiliar team.
- **Assessable practice:** Perform a cold handoff test and write a personal evidence index.
