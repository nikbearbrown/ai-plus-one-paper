# Chapter specifications

**Private Blueprint only. Draft route: `ready-for-draft-review`. Evidence: `matched-source`. No sign-off.**

Each entry is a proposed chapter, not drafted prose.

## 1. Decide which need deserves a project

- **Observable capability:** Convert competing claims into comparable project proposals
- **Teaching blocks:** portfolio fit; current capability; sponsor and users; selection criteria
- **Original worked example to write:** A neighborhood library has three digitization requests and funding for one.
- **Assessable practice:** Rank options with a transparent matrix and show what change would flip the decision.

## 2. Choose a delivery pattern

- **Observable capability:** Justify planning and feedback cadence for a specific uncertainty
- **Teaching blocks:** predictive vs iterative planning; value slices; Kanban; dependency uncertainty
- **Original worked example to write:** A volunteer inventory migration has a fixed cutover but unclear interface needs.
- **Assessable practice:** Lay out the hybrid approach and identify which deliverable benefits from iteration.

## 3. Estimate without pretending to know

- **Observable capability:** Evaluate how cost, risk, and capacity assumptions affect the plan
- **Teaching blocks:** budget constraints; risk register; scenario sensitivity; resource allocation
- **Original worked example to write:** One staffing assumption makes a backlog reduction plan look easy.
- **Assessable practice:** Compute two alternate scenarios and identify the first escalation point.

## 4. Govern through the project lifecycle

- **Observable capability:** Set decision rights and leading indicators for corrective action
- **Teaching blocks:** decision ownership; gates; project monitoring; benefits measures
- **Original worked example to write:** A mock reporting change appears green until an interface dependency slips.
- **Assessable practice:** Write two checkpoints with evidence requirements and a justified response when a checkpoint fails.

## 5. Make the recommendation explainable

- **Observable capability:** Defend a proposal and revise it after a change in constraints
- **Teaching blocks:** one-page case; assumptions ledger; alternatives; handoff
- **Original worked example to write:** A public-service intake tool loses half its initial budget at review.
- **Assessable practice:** Defend a re-scoped project using a portfolio argument and a numbered decision log.
