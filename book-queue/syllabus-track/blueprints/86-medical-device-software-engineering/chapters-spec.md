## 1. Bound the simulated system

- **Observable capability:** Describe what a status sample can and cannot establish
- **Teaching blocks:** nonclinical requirement; software boundary; data lifecycle
- **Original worked example to write:** Toy status heartbeat from an imaginary dashboard
- **Assessable practice:** Label evidence and unsupported interpretations

## 2. Trace requirements to software tests

- **Observable capability:** Show test ownership and coverage
- **Teaching blocks:** requirements IDs; verification matrix; expected outcomes
- **Original worked example to write:** Synthetic stale-frame status flag
- **Assessable practice:** Add a test preserving an unrelated status behavior

## 3. Investigate a mock anomaly

- **Observable capability:** Distinguish logging and presentation faults
- **Teaching blocks:** event order; fixture replay; escalation documentation
- **Original worked example to write:** Conflicting simulated log and dashboard status
- **Assessable practice:** Reconcile using an independent toy trace

## 4. Review the simulated release packet

- **Observable capability:** Assess a claim by its verification evidence
- **Teaching blocks:** provenance; change impact; exceptions
- **Original worked example to write:** Mock review of a status-message change
- **Assessable practice:** Decline an unsupported claim and state the missing software-only test
