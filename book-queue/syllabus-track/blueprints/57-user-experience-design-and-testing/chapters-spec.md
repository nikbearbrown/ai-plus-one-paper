# Chapter specifications

**Private Blueprint only. Draft route: `compare-scope`. Evidence: `matched-source`. No sign-off.**

Each entry is a proposed chapter, not drafted prose.

## 1. From complaint to observation

- **Observable capability:** Convert a vague complaint into a testable user task
- **Teaching blocks:** research question; task setting; sampling; consent
- **Original worked example to write:** A fictional campus print kiosk is criticized as hard to use.
- **Assessable practice:** Draft three observations and one disconfirming event without assuming what users want.

## 2. Map two plausible journeys

- **Observable capability:** Build competing flows with explicit states and failure points
- **Teaching blocks:** journey steps; information ordering; recovery; hypothesis
- **Original worked example to write:** A makerspace reservation can be started from a calendar or a room overview.
- **Assessable practice:** Draw both flows and match one design choice to a testable hypothesis.

## 3. Prototype only what the question needs

- **Observable capability:** Choose appropriate fidelity for a stated test
- **Teaching blocks:** paper and low fidelity; cue visibility; accessibility; constraints
- **Original worked example to write:** A shelter shift-swap mockup changes just the confirmation screen.
- **Assessable practice:** Construct two low-fidelity alternatives and articulate what the artifacts cannot test.

## 4. Run an honest usability check

- **Observable capability:** Write a neutral script and separate observations from interpretation
- **Teaching blocks:** recruiting criteria; task prompts; observation record; bias
- **Original worked example to write:** Two synthetic earlier user attempts failed for different reasons at one look-alike button.
- **Assessable practice:** Code observations without attributing motives and design a neutral follow-up.

## 5. Make the revision earn its place

- **Observable capability:** Defend one test-backed revision and one deliberate non-change
- **Teaching blocks:** synthesis; tradeoffs; success metrics; iteration
- **Original worked example to write:** A prototype revision improves one observed path but complicates another.
- **Assessable practice:** Produce an evidence-to-decision ledger and a limited follow-up test with a clear acceptance threshold.
