# Learning architecture

**Private Blueprint only. Draft route: `ready-for-draft-review`. Evidence: `matched-source`. No sign-off.**

## Proposed measurable outcomes

- Model responsibilities with class and interaction views
- Justify composition vs inheritance using a changing requirement
- Demonstrate substitute implementations under common tests
- Refactor without changing observable behavior
- Abstract creation from callers
- Model operations as interchangeable requests
- Defend cases where a simpler implementation wins

## Sequencing and final artifact

Part I establishes contracts, composition and observation-based refactoring. Part II introduces construction, requests and behavior wrappers as measured responses to change. Both parts have an independent end exercise; use a change-ready, tested catalog of repair appointments as the unifying original case.

## Assessment and AI Plus One practice

Mark a before/after change using invariant tests, a trace of new dependencies, an explanation of alternatives and an explicit reason to use or refuse the pattern. Assess behavior before style vocabulary. Ask for an independent first sketch, then have the learner verify any AI alternative with the same tests and two counterexamples.

Require a first attempt without AI; document any bounded AI assistance and independently check consequential outputs against evidence. These are original assessment recommendations, not institutional assignments or grading policy.
