# Object-Oriented Design and Design Patterns (AI Plus One)

**Private Blueprint only. Draft route: `ready-for-draft-review`. Evidence: `matched-source`. No sign-off.**

**Proposed spine:** Design tested objects around stable responsibilities, then introduce patterns only when a concrete change makes the simpler design inadequate.

**Proposed reader:** Graduate or advanced undergraduate programmer who has implemented small programs but has not designed larger collaborations.

**Observed syllabus evidence or limitation:** CSYE 6200 Fall CRNs 16348, 16350 and 16352, pp. 1–2, cover Java, interfaces, encapsulation, inheritance/composition, collections and engineering/testing. Spring CRN 35332, p. 2, puts materially more weight on named patterns; this is section variation, not uniform introductory scope. CSYE 6300 Fall CRN 21172 and Spring CRNs 37604 and 37605, p. 2, align on Java examples and separation of object creation, action execution and behavior wrapping; the Spring CSYE 6200 extract uses notably similar scope.

**Consolidation decision:** Merge CSYE 6200 and 6300: one adoptable progression from responsibilities, contracts and composition to a pattern specialization. Preserve different section emphasis without creating duplicate explanations. One progressive volume for the overlapping OO/patterns courses, with an independently adoptable upper part. Keep the product, persistence and delivery scope of Application Engineering separate; compare existing Java books for whether to use this as a design supplement.
